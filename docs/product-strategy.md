# Voo 产品定位与取舍准则

## 一句话

**尽可能本地，但效果优先；用户自备大模型 API 是可接受的增强，不是妥协。**

## 三条硬准则（冲突时的排序）

1. **效果 > 纯本地**：若本地做只能做到 80 分、加上用户自己的 LLM 能到 95 分，就做，并默认可用。
2. **本地优先，但本地不是信仰**：ASR、VAD、热词纠错留在本地；只有"语言理解/改写"这类本地做不好的事交给 LLM。
3. **隐私靠开关，不靠默认禁用**：敏感能力默认可用，提供明确开关与撤销；只有"拿到就会存进历史库"的数据（全屏文字、浏览器 URL、截图）不做。

## 能力分层（哪一层归谁）

| 层 | 归属 | 理由 |
| --- | --- | --- |
| 采集、重采样、电平调理 | 本地 | 实时性，云端做不了 |
| VAD、端点、停顿分段 | 本地 | 延迟敏感，且是隐私边界 |
| ASR 解码 | 本地 | 核心卖点，离线可用 |
| 拼音热词纠错 | 本地 | 快、可解释、可离线 |
| 术语表注入解码器 | 本地，默认关 | 实测易被带偏（Qwen/Fun-ASR），须逐模型验证 |
| 标点/口播整理/中英混排 | LLM（用户 API） | 本地规则做不到自然度 |
| 上下文感知纠错 | LLM（用户 API） | 少量上下文（app 名 + 游标前 ≤128 字符）即可显著提升 |
| 词库候选整理 | LLM（用户 API） | 只产出候选，不自动生效 |
| 从用户修正中学习 | 本地 diff → 候选 | 只在用户确认后生效 |

## 词库权限模型（四态，来自 sol 判定）

| 状态 | 权限 |
| --- | --- |
| Candidate | 只出现在建议里，不能改写 |
| Active-exact | 整词完全同音纠正 |
| Active-fuzzy | 近音纠正，**只能用户手动授予** |
| Blocked | 不再建议与激活，跨重导入保留 |

- 导入词典 → Candidate（不得直接进纠错索引）
- 「记住这个词」→ Active-exact
- 隐式信号（文档出现、历史频次、反复识别错）**只用于排序建议，不扩权**
- 批量词典只允许完整对齐、音节序列完全相同的匹配

## 已知教训（写下来避免重复犯错）

1. **合成信号不能当效果证据**：曾用白噪声断言"降噪有效"，实测对真实噪声仅 -1 dB。
2. **词表偏置是把双刃剑**：把 5000 个通用词塞进纠错索引，导致「什么时候」→「实模式候」。
3. **多音字会伪造"完全同音"**：什(shí)+么(mó)+时(shi) 能凑出「实模式」，因此完全同音也必须限制单读音对齐。
4. **延迟会重复计算**：VAD hangover 与分段器阈值叠加，导致"停顿即出字"从不触发（900 ms）。
5. **没有前视就不能承诺边界安全**：30 s 强制切分可能落在词中间，只能标记不可靠。

## 当前优先级（效果导向）

1. **识别主链路**：连续语句保留、电平调理、`/sil` 清理、导入词只做单音同音 —— 已完成
2. **LLM 后处理可用性**：默认 DeepSeek + Responses API + 语音场景 prompt + 词表注入（16 条/512 字符）—— 进行中
3. **上下文注入**：app 名 + 游标前 ≤128 字符（Windows UIA 优先），默认开可关 —— 进行中
4. **词库闭环**：Candidate/Active/Blocked 状态与徽章、「记住这条修正」—— 进行中
5. **LLM 整理词库 / 从修正学习**：只出候选，需确认 —— 待做
6. **停顿即出字**：已实现，待真机验证
