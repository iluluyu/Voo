### 固定算法与边界

1. **热词缓存**：以完整词表、规则文本、最短汉字数为精确 key，只保留一个已编译快照，以 `Arc` 复用；锁外编译、锁内比较与交换。阈值及近音代价保持不变。规则可在没有热词时独立生效。
   匹配候选先处理黑名单，同一输出目标合并最高分，只有不同目标参与歧义判定；正确热词的保护包括整句相等情况。
   独立审查发现数万词直接注入解码上下文的风险，收尾增加解码预算：最多 128 个去重目标词、总共 1024 个 Unicode 码点、每词不超过 64 码点，按生效列表顺序优先保留手工词；完整词库仍用于中文后处理。非汉字输出只用手工词做原有拉丁纠错，规则独立缓存，不构造导入词库的大索引。
2. **分类词库**：手工 `custom_words` 与 `imported_lexicons` 分开保存；生效列表为手工优先、来源名排序、稳定去重的并集。更新替换单来源快照，移除仅删除该来源。
   无法可靠判断旧 `custom_words` 中哪些来自历史导入，不自动迁移或删除这些词。只支持固定 THUOCL 分类，下载限制超时和体积，不实现未经授权的后台更新。
3. **降噪**：沿用已有 48 kHz 高通、特征及 FSM 阈值。真实 RNNoise 后端明确归一化/16-bit 幅度换算，干湿路对齐后按 `g·wet+(1-g)·dry` 混合。
   录音输入是 16 kHz，不能冒充 48 kHz；只有重采样、固定帧、延迟、finish 尾帧、跨录音 reset 均通过验证才接录音链路。否则仅交付明确标注的 48 kHz 离线实验。默认不启用，不宣称轻声识别一定改善。
4. **下载**：严格校验 `Content-Range` 单位、起止、总长、长度及实际 body；不因响应流结束就把不完整文件标记完成。取消和网络中断允许保留可续传数据，损坏元数据与越界数据拒绝使用。SHA256 仍是模型内容的信任锚。

## 验收方式

- 热词：规则-only、ASCII 规则、配置变化失效、缓存复用与并发、重复词/同目标别名、不同目标歧义及保护区回归。
- 词库：旧配置默认值、稳定并集、移除来源保留手工与其他来源、后台输入验证、下载失败/保存失败不报成功、前端类型与翻译一致。
- 降噪：真实后端幅度与有限值、任意分块一致、延迟/尾帧、reset；真实录音的 CER/术语召回 A/B 另行采集，不能用合成波形测试替代。
- 下载：本地 HTTP 脚本服务器覆盖合法续传、无效/矛盾/截断 range、额外 body、未知总长、取消；不依赖公网大模型下载。
- 全局：Rust tests、前端 build/Lint、翻译与目录检查、独立审查实际 diff。
- 配对评分：`scripts/evaluate-chinese.ts` 提供 CER、术语召回、标注负例误替换及延迟 P50/P95；见 [评估指南](chinese-evaluation.md)。

## 停顿分段（pause-commit）现状

`audio_toolkit/pause_commit.rs` 提供可测的分段事实：默认 400 ms 确认静音切分、短于
1 s 的片段等 800 ms 静音、说满 20 s 后 ≥200 ms 停顿即提交、30 s 仍无停顿强制切分。单测
覆盖不重叠、不漏样本（含尾块 valid_frames < 帧长时尾段不丢）、强制切分与自定义阈值。

**尚未接入生产录音链路**：启停时机、逐段上屏（焦点与撤销语义）、跨段标点与专名
质量都需要先做整段 vs 分段的 A/B。当前生产默认仍是整段转写。
