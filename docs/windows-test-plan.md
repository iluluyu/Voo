# Windows 开发与测试方案

本文件是 Voo 中文优化的 Windows 侧测试入口。自动化测试证明**代码契约**成立；
安装包能否真正输入中文、麦克风与粘贴是否可用，必须按[人工验收](#人工验收清单)在 Windows 实机跑一遍。

## 1. 自动化测试

在 Windows 侧检出目录执行（路径按实际调整，默认与现有 Windows 检出一致）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\test-windows-local.ps1 `
  -Checkout C:\Users\Administrator\voo\Voo
```

脚本会把每一步的 `VOO_TEST_RESULT <步骤> PASS|FAIL` 打印到控制台，并把完整输出
记录到 `C:\Users\Administrator\voo\test-report.log`；末尾输出
`VOO_TEST_SUMMARY pass=N fail=M`，有失败时以退出码 1 结束，方便 CI 或人工判断。

覆盖范围：

| 步骤         | 命令                                  | 验证内容                                                                             |
| ------------ | ------------------------------------- | ------------------------------------------------------------------------------------ |
| 前端构建     | `bun run build`                       | TypeScript + Vite 产物可生成                                                         |
| Lint         | `bun run lint`                        | 含 i18n 硬编码字符串规则                                                             |
| 键盘工具     | `bun run test:keyboard`               | 快捷键序列解析                                                                       |
| 词库来源保存 | `bun run test:lexicon`                | 逐来源串行写入、部分失败可见、IPC 异常不丢已保存来源                                 |
| 中文评估器   | `bun run test:chinese-eval`           | CER、术语召回、负例误替换、延迟分位、CLI 退出码、错误不回显原文                      |
| 翻译一致性   | `bun run check:translations`          | 25 种语言键完整                                                                      |
| 模型语言覆盖 | `bun run check:model-languages`       | catalog 语言码映射唯一                                                               |
| catalog 同步 | `bun run check:catalog`               | 与 `@handy-computer/models` 一致                                                     |
| Rust 格式    | `cargo fmt -- --check`                | 提交前格式                                                                           |
| 示例编译     | `cargo check --examples`              | 离线降噪工具等示例可编译                                                             |
| Rust 单测    | `cargo test --lib`                    | 转写管线、热词、词库、下载续传、降噪等全部单测                                       |
| 降噪离线冒烟 | `cargo run --example denoise_offline` | 48 kHz mono 输入 → float32 mono 输出、样本数相等、拒绝覆盖已有输出、拒绝原地改写输入 |

基线（Linux 本会话末次全量）：Rust **404 passed / 0 failed / 19 ignored**。Windows 侧若出现
平台相关失败，先记录失败用例名与错误文本再改代码，不要靠放宽断言过关。

### 手动触发的中文效果评估

自动化测试不评估识别准确率。用固定录音同上屏文本做 A/B：

```bash
bun run eval:chinese /path/to/paired-results.jsonl
```

数据格式与指标边界见 [中文输入 A/B 评估](chinese-evaluation.md)。
建议至少覆盖：安静/嘈杂、普通音量/轻声、短句/长句，以及"无词库 / 解码词库 / 解码词库+拼音纠错"三种配置。

## 2. 人工验收清单

安装包由 `scripts/build-windows-local.ps1` 生成，产物放在 `C:\Users\Administrator\voo\`
（未签名，仅本地测试；不要分发给终端用户）。

每项记录：通过/失败、实际现象、截图或 `voo.log` 片段。

### W1 安装与启动

1. 运行生成的 `Voo_*_x64-setup.exe`，装到默认目录。
2. 启动后托盘出现图标；首次启动应进入引导（权限/模型）。
3. 关闭主窗口应留在托盘，不退出进程。

**预期**：无崩溃、无"缺少 DLL"报错。若报缺少 `VCRUNTIME140.dll` 等，说明 VC++ 运行库未随包附带，记录具体 DLL 名。

### W2 麦克风与快捷键

1. 设置 → 选麦克风设备，观察电平条随说话变化。
2. 按住默认快捷键说话再松开；把同一操作改为"点按切换"再试。

**预期**：能开始/停止录音，录音中托盘与浮层状态一致；切换模式不需要重启。

### W3 中文转写与上屏

1. 选 Fun-ASR Nano 或 Qwen3-ASR，语言选中文（或自动）。
2. 在记事本、VS Code、浏览器地址栏各说一句中文。

**预期**：文字落到当前光标处；不在错误窗口重复输入；剪贴板按设置恢复。

### W4 拼音热词纠错

1. 设置 → 高级 → 自定义词汇，加入一个 4 字术语（例如 `模型量化`）。
2. 故意把该术语说成同音错字（如"模型亮化"）。
3. 再说一句不含该术语的话。

**预期**：同音错字被纠正为目标词；无关句子不被误改。若术语未纠正，记录是否命中 2 字门槛（拼音后处理默认只收录 ≥3 汉字）。

### W5 中文热词规则

1. 在"中文热词规则"里写 `人工智能=AI` 与一条正则 `四([个只])=>四条$1`。
2. 分别说出能被两条规则命中的句子。

**预期**：规则在拼音替换之后生效且不二次改写已被热词替换的片段；注释行 `#` 被忽略。

### W6 分类词库导入

1. 设置 → 高级 → 词库导入，勾选 `IT` 与 `medical`，点击预览。
2. 确认预览词数后保存；观察已安装来源列表与词数。

**预期**：两个来源各自显示词数与移除按钮；手工自定义词汇列表**不混入**导入词。

### W7 词库更新与移除

1. 对已安装来源再次导入（更新），保存后用"移除"删除其中一个来源。
2. 检查手工词汇仍完整，另一个来源仍生效；随后再说一个被移除来源里的术语。

**预期**：移除只影响该来源；手工词不被删除；被移除词不再被强制纠正。

### W7b 词库离线导入（网络完全不可用时）

1. 用浏览器/下载工具取到 `THUOCL_IT.txt`（GitHub `thunlp/THUOCL` 的 `data/` 目录）。
2. 设置 → 高级 → 词库导入：只勾 **一个** 分类 → 点「从本地文件导入…」→ 选中该文件。
3. 预览应出现词数与样例；保存后来源列表出现该分类。

**预期**：与联网导入得到同样过滤结果（纯汉字 2–50 字（先 trim）、DF 前 5000）；失败时错误文本可选中、可点「复制错误详情」。

### W8 网络异常与部分失败

1. 断网后预览一个未安装分类。
2. 保存多个分类时中途断网。

**预期**：失败给出明确错误提示，**绝不**提示成功；已成功保存的来源可见，未成功的可重试；不出现界面永久卡在加载状态。

### W9 模型下载与续传

1. 下载一个中文模型，中途暂停/取消，再继续。
2. 断开网络若干秒后恢复（触发 stall 超时），观察是否可续传。

**预期**：续传后文件校验通过、可正常加载；损坏或被篡改的响应不会把半截文件当作完成。

### W10 非中文内容不受影响

1. 把语言切到英文，说一句含自定义英文词的句子。
2. 导入大词库后重复上面这句。

**预期**：英文纠错仍按手工词生效；导入的纯汉字词库不改变英文结果，也不引入明显延迟。

### W10b 输入电平调理（轻声/大声）

1. 设置 → 高级 → 确认「输入电平调理」为**开**（默认）。
2. 以正常音量、耳语音量、较大音量分别说同一句中文，各 3 次。
3. 每次看 `voo.log` 里 `Input leveler at stop:` 的 gain / floor / clipped。

**预期**：耳语的识别率明显高于关闭该开关时；正常与大声**不变差**；办公室底噪不触发误识别。若 `clipped samples` 很大，说明采集端已削顶——只能降低系统麦克风增益，软件救不回来。

### W11 简繁与语言切换

1. 在设置中切换"中文输出字形"（原文/简体/繁体）。
2. 切换到日文或其他语言各说一句。

**预期**：仅中文输出按设置转换；其他语言不被改写。

### W12 历史与日志

1. 设置 → 历史，检查刚才的转写记录与耗时。
2. 通过界面"打开日志目录"定位 `voo.log`，确认无 panic，错误行有上下文。

## 3. 本轮未交付、不要按"已验证"登记

- **实时降噪**：16 kHz 录音尚未接入，只有 48 kHz 离线工具可跑，见[实验降噪](experimental-denoise.md)。
  验收时不要期待开关或音质变化；离线工具的正确性由自动化测试覆盖。
- 分类词库的订阅 URL 与后台定期更新。
- 转写后自动学习用户修改、MCP server。
- 跨设备同步、安装包签名与自动更新（本测试包已显式关闭签名）。

## 4. 常见问题

- **打包失败 `failed to bundle project: program not found`**：本地测试包若未关闭
  `bundle.windows.signCommand`，会尝试调用 `trusted-signing-cli`。构建脚本已在临时检出里
  生成 `src-tauri/tauri.local.test.json` 关闭签名，发布配置未被修改。
- **`Could not create named generator Visual Studio 18 2026`**：`transcribe-cpp-sys` 让
  `cmake` crate 自选生成器，VS 18 环境会推出该 CMake 不认识的生成器名。构建脚本设置
  `CMAKE_GENERATOR=Ninja`（VS Build Tools 自带 Ninja）绕开。
- **构建目录不要放在 WSL 的 `\\wsl.localhost\...` 上**：9p 网络盘会显著拖慢 CMake/rustc，
  且部分工具拒绝 UNC 路径；Windows 检出应位于本地 NTFS 目录。
